- [x] 6. 修正を実施した
- [x] 7. 動作確認を完了した
- [x] 8. TodoWrite のタスクを完了にした

### 採用した解決策
会話画面を開いた時に自分のunreadCountを0にリセットするuseEffectを追加

### 学んだこと
- メッセージ機能では送信時のカウント更新だけでなく、閲覧時のリセット処理も必要

### 問題の詳細
- メッセージを受信するとアプリに通知バッジが表示される
- 会話画面を開いてメッセージを確認しても、バッジが消えない
- 未読状態が解除されていない

### 原因分析
コード検索結果:
```bash
grep -r "unreadCount.*=.*0|resetUnread|markAsRead" /mobile/src
```
→ **unreadCount をリセットするコードが存在しない**

**問題のフロー:**
1. メッセージ送信時: `unreadCount.${friendId}` が `increment(1)` される（正常）
2. 会話画面を開く: **unreadCount をリセットする処理がない** ← 問題
3. バッジ計算: `unreadCount[userId]` の合計が常に増え続ける

### 修正計画

#### Step 1: ConversationScreen.tsx に unreadCount リセット処理を追加
会話画面を開いた時に、自分の unreadCount を 0 にリセット:

```typescript
useEffect(() => {
  if (!user || !conversationId) return;

  // 自分の未読カウントをリセット
  const resetUnreadCount = async () => {
    const db = getFirestoreInstance();
    await updateDoc(doc(db, 'conversations', conversationId), {
      [`unreadCount.${user.uid}`]: 0,
      updatedAt: serverTimestamp(),
    });
  };

  resetUnreadCount();
}, [conversationId, user]);
```

#### Step 2: 動作確認
- メッセージ受信 → バッジ表示
- 会話画面を開く → バッジが消える

### 修正ファイル
- /mobile/src/screens/messages/ConversationScreen.tsx

- [x] 7. 動作確認を完了した
- [x] 8. TodoWrite のタスクを完了にした

### 採用した解決策
1. collectionGroup(db, 'messages')を使用してサブコレクションを横断検索
2. firestore.indexesにCOLLECTION_GROUPインデックスを追加
3. firestore.rulesにcollectionGroup読み取りルールを追加

### 学んだこと
- サブコレクションのデータを横断検索するにはcollectionGroupが必要
- collectionGroupにはインデックスとセキュリティルールの両方が必要
- デバッグビルドでないとコード変更が反映されない場合がある

### 追加調査（2026-05-25 15:20）
前回の修正（collectionGroupへの変更、インデックス追加、ルール追加）を実施したが問題が解決していない。

**確認済み項目:**
1. ✅ firestore.indexes.json に COLLECTION_GROUP インデックス追加済み
2. ✅ firestore.rules に collectionGroup 読み取りルール追加済み
3. ✅ firebase deploy 成功、インデックスは READY 状態
4. ✅ ConversationScreen.tsx を collectionGroup(db, 'messages') に変更済み

**新たな問題仮説:**
onSnapshot のエラーハンドラがなく、クエリが失敗してもサイレントに失敗している可能性。
→ エラーハンドリングとログを追加済み

**次のステップ:**
アプリを再ビルドしてログを確認し、実際のエラーを特定する

### 問題の詳細
- 無課金ユーザーの残りメッセージ回数が10回から変化しない
- 月10回の制限が機能していない

### 原因分析
ConversationScreen.tsx (119-138行目) でメッセージカウントを取得するクエリ:
```typescript
const q = query(
  collection(db, 'messages'),  // ← ルートレベルの'messages'を参照
  where('senderId', '==', user.uid),
  where('createdAt', '>=', Timestamp.fromDate(startOfMonth))
);
```

しかし実際のメッセージは `conversations/{conversationId}/messages` というサブコレクションに保存されている。
ルートレベルの `messages` コレクションは存在しないか空のため、常に0件が返される。

### 修正計画

#### Step 1: collectionGroup を使用したクエリに変更
```typescript
import { collectionGroup } from 'firebase/firestore';

const q = query(
  collectionGroup(db, 'messages'),
  where('senderId', '==', user.uid),
  where('createdAt', '>=', Timestamp.fromDate(startOfMonth))
);
```

#### Step 2: Firestoreルールに collectionGroup クエリを許可するインデックスを追加
firestore.indexes.json に以下を追加:
```json
{
  "collectionGroup": "messages",
  "queryScope": "COLLECTION_GROUP",
  "fields": [
    { "fieldPath": "senderId", "order": "ASCENDING" },
    { "fieldPath": "createdAt", "order": "ASCENDING" }
  ]
}
```

#### Step 3: Firestoreルールで collectionGroup 読み取りを許可
```javascript
match /{path=**}/messages/{messageId} {
  allow read: if isAuthenticated() &&
    resource.data.senderId == request.auth.uid;
}
```

### 修正ファイル
- /mobile/src/screens/messages/ConversationScreen.tsx
- /firestore.indexes.json
- /firestore.rules

await updateDoc(doc(db, 'conversations', conversationId), {
  lastMessage: messageText,
  lastMessageAt: serverTimestamp(),  // ← この更新が拒否される

`lastMessageAt` を許可リストに追加:
```javascript
.hasOnly(['lastMessage', 'lastMessageAt', 'unreadCount', 'updatedAt'])
```

#### Step 2: Firebaseにデプロイ
```bash
firebase deploy --only firestore:rules
```

## Problem #12: 友達承認時に「エラーが発生しました」と表示される
発生日: 2026-05-25
関連Phase: Phase 18
ステータス: 解決済み

### 必須チェックリスト（全て完了必須）
- [x] 1. problem.txt の過去事例を確認した
- [x] 2. TodoWrite に問題対応タスクを追加した
- [x] 3. 原因を徹底調査した
- [x] 4. 修正計画を作成した
- [x] 5. problem.txt に記録した（この項目）
- [x] 6. 修正を実施した
- [ ] 7. 動作確認を完了した
- [ ] 8. TodoWrite のタスクを完了にした

### 問題の詳細
- 招待コードで友達を追加後、友達申請を承認しようとするとエラーが発生
- 「友達を承認する」ボタンを押すと「エラーが発生しました」とアラート表示
- 友達追加ができない状態

### 原因分析
**根本原因**: Firestoreセキュリティルールが `conversations` コレクションの `status` フィールド更新を許可していない

**コード追跡**:
1. `ConversationScreen.tsx:170-185` で `handleAccept` 関数が呼ばれる
2. `friendRequest.ts:129-145` の `acceptFriendRequest` で `updateDoc` を実行
3. 更新内容: `{ status: 'active', updatedAt: serverTimestamp() }`

**セキュリティルール（firestore.rules:64-66）**:
```javascript
allow update: if isParticipant(resource.data) &&
  request.resource.data.diff(resource.data).affectedKeys()
    .hasOnly(['lastMessage', 'unreadCount', 'updatedAt']);
```

`status` フィールドは許可リストに含まれていないため、更新が拒否される。

### 修正計画

#### Step 1: firestore.rules の更新
`conversations` コレクションの更新ルールに `status` フィールドを追加する。
ただし、以下の条件を満たす場合のみ：
- `pending` → `active`: リクエストを受け取った側（requestFromUserId以外のparticipant）のみ
- 参加者であること

```javascript
// 更新: 参加者のみ
allow update: if isParticipant(resource.data) &&
  (
    // メッセージ関連の更新
    request.resource.data.diff(resource.data).affectedKeys()
      .hasOnly(['lastMessage', 'unreadCount', 'updatedAt'])
    ||
    // ステータス変更（pending → active）: リクエスト受信者のみ
    (resource.data.status == 'pending' &&
     request.resource.data.status == 'active' &&
     resource.data.requestFromUserId != request.auth.uid &&
     request.resource.data.diff(resource.data).affectedKeys()
       .hasOnly(['status', 'updatedAt']))
  );
```

#### Step 2: Firebaseにデプロイ
```bash
firebase deploy --only firestore:rules
```

#### Step 3: 動作確認
- シミュレーターで友達申請を承認できることを確認
- 実機でも同様にテスト

### 修正ファイル
- /firestore.rules

- /metro.config.js
- /src/services/firebase.ts

### 実施した修正内容

#### 1. metro.config.js
```javascript
const config = {
  resolver: {
    unstable_enablePackageExports: true,
    unstable_conditionNames: ['react-native', 'browser', 'require'],
  },
};
```

#### 2. firebase.ts

## Problem #10: アプリ起動時に毎回ログイン画面が表示される（追加修正）
発生日: 2026-05-16
解決日: 2026-05-18
関連Phase: Phase 18
ステータス: 解決済み

### 必須チェックリスト（全て完了必須）
- [x] 1. problem.txt の過去事例を確認した
- [x] 2. TodoWrite に問題対応タスクを追加した
- [x] 3. 原因を徹底調査した
- [x] 4. 修正計画を作成した
- [x] 5. problem.txt に記録した（この項目）
- [x] 6. 修正を実施した
- [x] 7. 動作確認を完了した
- [x] 8. TodoWrite のタスクを完了にした

### 問題の詳細
- アプリを毎回起動するとオンボーディング画面が表示される
- その後ログイン画面に遷移し、毎回ログインが必要
- 一度ログインしたらホーム画面（ダミー画面）まで自動で進むべき
- ただし、設定画面・メッセージ画面へのアクセス時は毎回パスワード認証を求める（現状通り）

### 原因分析
Firebase JS SDK を React Native で使用する場合、デフォルトの認証永続化（IndexedDB）が機能しない。
`getReactNativePersistence` と `AsyncStorage` を使った明示的な永続化設定が必要。

**現状のコード** (`firebase.ts`):
```typescript
auth = getAuth(firebaseApp);  // ブラウザ用の永続化のみ
```

Firebase JS SDK は Web ブラウザ向けに設計されており、React Native 環境では
IndexedDB が利用できないため、セッションが永続化されない。

### 修正計画

#### Step 1: firebase.ts の修正
`getReactNativePersistence` を使用して AsyncStorage ベースの永続化を設定

```typescript
import { initializeAuth, getReactNativePersistence } from 'firebase/auth';
import AsyncStorage from '@react-native-async-storage/async-storage';

auth = initializeAuth(firebaseApp, {
  persistence: getReactNativePersistence(AsyncStorage)
});
```

#### Step 2: RootNavigator の確認
オンボーディング完了後、認証状態に応じた画面遷移が正しく動作することを確認
- オンボーディング未完了 → オンボーディング画面
- オンボーディング完了 & 未ログイン → 認証画面
- オンボーディング完了 & ログイン済み → ホーム画面（ダミー画面）

#### Step 3: accessStore の確認
設定画面・メッセージ画面へのアクセス時のパスワード認証は毎回要求されることを確認
（accessStore の認証状態はメモリ上のみで永続化しない＝現状維持）

### 修正ファイル
- /src/services/firebase.ts
- /tsconfig.json（TypeScript設定追加）
- /metro.config.js（Package exports有効化）
- /src/navigation/RootNavigator.tsx（authStore.initialize()追加）

### 実施した修正内容
1. `firebase.ts` を修正:
   - `initializeAuth` と `getReactNativePersistence` を使用
   - AsyncStorage ベースの永続化を設定

2. `tsconfig.json` を修正:
   - `moduleResolution: "bundler"` を追加
   - `customConditions: ["react-native"]` を追加

3. `metro.config.js` を修正（Problem #11対応）:
   - `unstable_enablePackageExports: true` を追加
   - `unstable_conditionNames: ['react-native', 'browser', 'require']` を追加

4. `RootNavigator.tsx` を修正（追加修正 2026-05-18）:
   - `authStore.initialize()` の呼び出しを追加
   - Firebase Auth の状態監視を開始するように修正
   - `isInitialized` を使用してローディング判定

- iOSビルド: BUILD SUCCEEDED
